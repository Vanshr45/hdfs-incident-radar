HDFS Incident Radar · a predictive analytics project · CA2

of storage blocks went wrong. Could a computer find them?

In , a Hadoop cluster of machines wrote log lines in hours. Every file it stored was cut into blocks, and every block left a trail of lines about what happened to it. I treated each trail as a diary, counted what was in it, and trained models to tell healthy diaries from broken ones. This page is what I found — including the blocks my best model still gets wrong.

By Vansh · every number on this page is read from files my notebooks saved

Hadoop splits files into blocks and keeps copies of each one on different machines. The cluster in my dataset handled blocks in hours.

            12

            What this does not show

            • It counts steps and ignores their order. A block whose steps arrived in a strange order, but in normal numbers, looks healthy to every model here.
            • It is one cluster in . machines, hours, one Hadoop version, benchmark jobs. I have no evidence the cut-off would carry over to anything else.
            • The labels came from rules, not from failures someone confirmed. My models learned to agree with those rules.
            • Patterns, not causes. Event counts describe associations and do not establish why a block failed.
            • Completed histories. This is retrospective classification, not an early-warning or real-time system. The grouped test assesses unseen count patterns from the same benchmark, not a different system.
            • Test reuse. The grouped test was evaluated twice during the update. The later restriction to four primary classifiers followed the original project request; the recorded workflow shows model settings, feature selection and thresholds were not adjusted from test results. Future tuning should not use these inspected results.

            13

            How I did it

            Data. Loghub HDFS_v1, Zenodo record : log lines grouped into blocks. Models use event counts; E22 is constant in training. Block ID, matrix Label and Type are excluded.

            Split. Identical event-count patterns are kept together, yielding training, validation and test blocks. Groups are allocated to approximately balance class counts. The original stratified row split is retained as a separate benchmark.

            Course topics. Preprocessing, correlation, logistic regression, k-nearest neighbours, Naive Bayes, decision trees and rules, linear SVM, k-means, PCA, a small neural network, bias-variance, bagging (random forest), boosting (AdaBoost), and accuracy, precision, recall, F1, AUC, log loss and confusion matrices.

            Cut-offs. Every model’s cut-off is the one with the lowest validation cost; a block raises the alarm when its score is at or above it.
